Context:
We are preparing the robust asynchronous transcription application for production deployment. Currently, there are hardcoded paths and specific project variables in the code (e.g., /Users/koen/...json, project ID, and language codes). We need to extract all configuration out of the Python code to make it cross-platform and easy to deploy on a Windows machine in the church.

Objective:
Refactor the codebase to use environment variables for all configuration, utilizing the python-dotenv package.

Requirements:

Implement python-dotenv:

Import and call load_dotenv() at the very top of the application script.

Add python-dotenv to the requirements.txt.

Refactor TranscriptionEngine Initialization:

Remove the hardcoded self.credentials_path. Replace it with os.getenv("GOOGLE_APPLICATION_CREDENTIALS").

Remove the hardcoded self.project_id. Replace it with os.getenv("GOOGLE_PROJECT_ID").

Remove the hardcoded languages ("nl-NL", "en", "fr"). Fetch them via os.getenv("SOURCE_LANG", "nl-NL"), os.getenv("TARGET_LANG_1", "en"), and os.getenv("TARGET_LANG_2", "fr").

Add basic error handling during initialization: if GOOGLE_APPLICATION_CREDENTIALS or GOOGLE_PROJECT_ID is missing, throw a clear and helpful ValueError instructing the user to check their .env file.

Create a .env.example file:

Generate a template file named .env.example that includes all the required environment variables with placeholder values. This will serve as documentation for setting up the application on a new machine.

Expected Output:
Please provide the updated app.py (or the main script), the new .env.example file, and the updated requirements.txt. Ensure no hardcoded personal paths remain in the code.
